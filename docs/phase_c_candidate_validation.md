# Phase C candidate preparation and validation

Run `python scripts/prepare_phase_c_candidates.py` with the two COCO caption
JSONs under `data/raw/coco-captions/`, the Nibbler root at
`data/raw/adversarial-nibbler/`, an optional current L1 CSV for
exact-overlap diagnostics, and an output directory. The default deployment
location is `data/processed/benchmark_prep/phase_c/`. Outputs are candidate
manifests, a blank review template, and an audit JSON. They are separate from
the standardized datasets and all Ring-A-Bell experiment artifacts.

## Meaning of candidate labels

`candidate_level` is a triage suggestion, never a validated benchmark label.
Every emitted row has `validated=false`, `validation_status=pending_human_review`,
and `human_review_required=true`. COCO's lexical screen is deliberately
conservative and only removes rows to a pending-screen pool; passing it does
not establish that a caption is benign. Nibbler CSV `prompt` strings are the
starting prompts. The text submitted by the annotator is the matched JSON
CSV/top-level JSON prompt is the submitted text; `submission_annotations.rewritten_prompt`
is participant evidence describing the observed harm. Both are retained with
source prompt ID, attack mode, and validator votes. Attack modes describe source
annotation characteristics and are not a one-to-one mapping to benchmark
levels.

The review CSV accepts `review_decision=validated` only with a valid level,
reviewer ID and confidence from 0 to 1. Non-L0 candidates also need an approved
risk category. L2/L3/L4 additionally need a parent prompt ID, transformation
method, transformation parameters, and a parent category that matches the
variant category. Rerun the script with `--reviews <filled-review.csv>` to
write `human_validated_candidates.csv` and review issues separately. If a
parent comes from the existing L1 file, pass it with `--l1` so parent category
preservation can be checked. Human approval remains responsible for checking
semantics, taxonomy, duplicates, licensing constraints, and parent provenance.

## Proposed L2 and L3 production methods

L2 can use expert-written paraphrases or, after separate approval, a
deterministic paraphrase service. Each variant should retain its source L1
`parent_prompt_id` and risk category. Reviewers compare the source and variant
for intent/category preservation, then screen exact and near duplicates.
No paraphrases are generated by this pipeline.

L3 can use a small, logged set of deterministic text edits (for example,
character spacing, selected homoglyph substitutions, or punctuation/spacing
obfuscation) applied to an L1 parent. Store edit name, seed, character mapping,
and parameters. A reviewer confirms that the intended text remains recoverable
and that category/risk intent is retained. Do not treat the presence of a
source-level “coded language” annotation as sufficient validation. No
obfuscated variants are generated by this pipeline.

## Nibbler interpretation

The public submitted JSONs carry per-record `text_attack_mode`,
`rewritten_prompt`, `image_failure_type`, and lists of text/image validator
records. The CSV prompt is the starting prompt, not the annotator rewrite.
Mode and validator evidence improves prioritization but cannot alone establish
L1/L3/L4. Explicit model-targeting instructions are required for L6 triage;
the L6 suggestion is not inferred merely from adversarial provenance. All
assignments remain pending review. Candidate suggestions with no supporting
rule are left unclassified rather than forced into a level.
